# Мини-приложение КлиентРадар — архитектура и план

Мини-приложение (Telegram Mini App) — «кабинет» внутри Telegram: открывается кнопкой у бота, выглядит как сайт, но входит сам, по аккаунту Telegram.
Бот остаётся главным (заявки приходят в чат, ответ в один клик). Приложение — для того, где в чате неудобно: списки, доска сделок, настройки, цифры.

## 1. Принципы
1. **Одна база, одна логика.** Приложение не дублирует правила: оно вызывает те же функции из `app/services/*`, что и бот. Что нельзя в боте — нельзя и в приложении.
2. **Права только на сервере.** Роль (админ / 💎 платный / бесплатный) берётся из базы по проверенному `initData`, а не из того, что прислал браузер.
3. **Внутренний `feed` (порт 8090) не открываем в интернет.** Для приложения — отдельный публичный порт 8091 за HTTPS.
4. **Лёгкое.** 1 ГБ RAM: без Node/сборки на сервере, без новых контейнеров с базами. Страница — статичные файлы + небольшой JSON-API внутри существующего процесса бота.
5. **Бот-дублёр.** Каждый экран приложения имеет «запасной путь» в боте. Приложение упало — работа не встала.

## 2. Схема
```
Telegram (телефон)
   │  кнопка «📱 Кабинет» (WebApp)
   ▼
https://<домен>/app/            ← Caddy (HTTPS, сертификат сам)
   ├─ /app/*     → статичные файлы (HTML + JS + CSS), без сборки
   └─ /api/*     → aiohttp внутри процесса бота, порт 8091
                      │  проверка initData (подпись BOT_TOKEN)
                      ▼
                  app/services/*  → SQLite (та же data/crm.db)
```
- **Caddy** — отдельный маленький контейнер (≈20–30 МБ RAM), сам получает и продлевает сертификат Let's Encrypt.
- **API** — новый модуль `app/web/` (`server.py`, `auth.py`, `routes_*.py`), запускается рядом с `feed` в `main.py`.
- **Фронтенд** — папка `webapp/`: один `index.html`, Preact+htm с CDN (без `npm build`), тема берётся из Telegram (`themeParams`), поддержка тёмной темы.
- **Общая SQLite** уже работает в режиме одного процесса; приложение живёт в нём же → блокировок между процессами нет.

## 3. Вход и безопасность
- Приложение получает от Telegram строку `initData`; сервер проверяет подпись HMAC-SHA256 ключом, выведенным из `BOT_TOKEN`, и срок (`auth_date` не старше 24 ч).
- Из проверенных данных берём `user.id`; пользователь ищется в `users` — **нет в базе или не прошёл регистрацию → приложение показывает «сначала /start в боте»**.
- Каждый запрос `/api/*` несёт `initData` в заголовке `Authorization: tma <initData>`; сессий и паролей нет.
- Роль определяется заново на каждый запрос (`is_admin`, `is_paid`) — продление или блокировка действуют сразу.
- Админские методы `/api/admin/*` дополнительно проверяют `is_admin`; заблокированным (`blocked`) — отказ.
- Лимиты: не более N запросов в минуту на пользователя; платёжные действия — только через те же серверные функции (деньги ЮKassa по-прежнему подтверждает сервер, не браузер).
- Данные чужих людей (ники, номера, тексты авторов заявок) — как в боте: показываем только то, что бот и так присылает владельцу заявки.
- CORS закрыт, заголовки безопасности (CSP) — на Caddy. Логи без `initData`.

## 4. Экраны по ролям (кто что видит)
Доступ — по тарифу и настройкам бота (`free_daily_limit`, `free_delay_min`, `ai_*`, цены и т. д. читаются из `settings`).

| Экран | 🆓 Бесплатный | 💎 Платный | 👑 Админ |
|---|---|---|---|
| **Главная**: сегодня заявок, в работе, напоминания, тариф, «⚡ Автонастройка» | да (лимит и задержка видны) | да | да + «состояние бота» |
| **Заявки**: лента, фильтр по нише/статусу, «Взять», «Отложить», «Спам», «Коллеге» | в рамках дневного лимита | без лимита | все |
| **CRM-доска**: клиенты по этапам (перетаскивание), заметки, бюджет, напоминания | да | да | да |
| **Профиль/настройки**: ниши, город, минус-слова, тишина, шаблон, цены, пауза | да | да | да |
| **Каталог**: группы, бонусы, мои группы, добавить группу, реклама | да | да | + модерация заявок |
| **Тариф и оплата**: цены, оплата ЮKassa (СБП/карта), срок, возврат по условиям | купить | продлить | история платежей |
| **Друзья**: ссылка, сколько пришло, награды | да | да | да |
| **Статистика**: свои цифры | да | да | + весь бот, воронка, выручка |
| **Управление ботом**: настройки по разделам с подсказками, пресеты, поиск, автонастройка | — | — | да |

Экран «⚡ Автонастройка» одинаковый по смыслу в боте и в приложении: показывает, что заполнит (только пустое), что осталось выбрать самому; у админа — ещё чек-лист готовности бота.

## 5. API (черновик)
Все ответы JSON, ошибки `{error, message}`.

Пользователь:
- `GET  /api/me` — профиль, тариф, роль, права (что показывать в меню)
- `GET  /api/leads?status=&category=&cursor=` · `POST /api/leads/{id}/take|snooze|spam|pass`
- `GET  /api/clients` · `PATCH /api/clients/{id}` (этап, заметка, бюджет, напоминание)
- `GET/PUT /api/profile` — ниши, город, минус-слова, тишина, шаблон, цены, пауза
- `GET  /api/autosetup` · `POST /api/autosetup` — предпросмотр и применение
- `GET  /api/catalog` · `POST /api/catalog/submit` · `GET /api/referrals`
- `GET  /api/plans` · `POST /api/pay` (создаёт платёж, возвращает ссылку ЮKassa)
- `GET  /api/stats`

Админ (`/api/admin/*`): `status`, `settings` (список/изменение с `HINTS`), `presets` (+применение), `users`, `groups`, `broadcast`, `licenses`, `blacklist`.

Каждый метод — тонкая обёртка над существующей функцией сервиса; новой бизнес-логики в `app/web/` нет.

## 6. Как открывается
- В боте: кнопка «📱 Кабинет» в профиле и `MenuButtonWebApp` вместо списка команд (команды остаются через `/`).
- Из заявки: «Открыть в кабинете» ведёт сразу на нужную карточку (`startapp=lead_123`).
- Для телефона: крупные кнопки, нижняя навигация (Главная · Заявки · Клиенты · Ещё), нативные `MainButton`/`BackButton`, вибро-отклик, без hover-эффектов.

## 7. Что нужно от владельца до начала
1. **Домен с HTTPS** (Telegram открывает мини-приложения только по https). Варианты:
   - свой домен (~200 ₽/год) — запись A на IP сервера;
   - бесплатно: поддомен вида `<ip-через-дефисы>.sslip.io` или DuckDNS — Caddy выпустит сертификат сам.
2. Открыть порты 80 и 443 на сервере (Selectel) и в `ufw`.
3. Решить порядок этапов (ниже).

## 8. Этапы
- **М0 — каркас (1 сессия):** Caddy + `app/web` + проверка `initData` + экран «Главная» + кнопка в боте. Тесты подписи (в т.ч. поддельная и просроченная).
- **М1 — ядро пользователя:** Заявки, профиль/настройки, автонастройка, тариф (только просмотр).
- **М2 — CRM-доска** и напоминания, друзья, каталог.
- **М3 — оплата** в приложении (ссылка ЮKassa/СБП) и статистика.
- **М4 — админка:** состояние бота, настройки с подсказками, пресеты, пользователи, группы, рассылка.
- **М5 — шлифовка:** тёмная/светлая тема, скорость, офлайн-заглушка, русские тексты, замер памяти на сервере.

## 9. Риски и ответы
- **Память 1 ГБ:** API внутри уже работающего процесса + Caddy; статика отдаётся Caddy, не Python. Замер после М0.
- **Подделка запросов:** без валидной подписи Telegram ничего не работает; роль всегда из базы.
- **Расхождение бота и приложения:** общий слой `services`, тесты на оба входа.
- **Домен/сертификат не настроен:** бот продолжает работать как раньше, кнопка кабинета не показывается, пока не задан `WEBAPP_URL` в `.env`.
