# ИИ: проверенное устройство и план улучшений
Дата: 15.11.2026. Аудит исходников рабочей ветки на a472d276852e900bc37b5e77e5e6da8b12905168. Содержимое ai.py, brain.py, llm.py, offers.py, groupcheck.py, queryideas.py и AI_PLAN.md сверено по Git blob SHA с репозиторием. Это проверка кода, не новый вызов модели и не проверка текущих настроек сервера.

## Уже реализовано
- llm.py: выбор GigaChat, YandexGPT, Ollama или отдельного пути Claude; конфигурация провайдера, таймауты и обработка ошибок.
- offers.py: правила и похожие примеры из отметок администратора, затем ИИ отличает заказчика, исполнителя, неподходящую нишу и прочее. При ai_check_leads=1 проверяет также прошедшие первичные правила сообщения. Явно отсеянные правилами сообщения модель не рассматривает. Отметки — похожие примеры, не дообучение весов модели.
- groupcheck.py: качество групп по выборке сообщений, спам/не по теме, дополнение географии. Вывод влияет на вступление и аудит групп; защищённые группы обрабатываются отдельно.
- queryideas.py: раз в неделю до 15 дополнительных поисковых запросов на круг, Дагестан → Кавказ → Россия. ИИ придумывает запросы, реальные группы ищет Telegram.
- brain.py и publisher.py: условия рекламы, закрепы и сообщения ботов; часы, платная реклама/только администратор, контакт. Не заменяет согласия администратора.
- brain.py, handlers/adposts.py, services/adposts.py: проверка рекламного текста и подбор до 5 площадок из переданного списка. Проверка не является гарантией законности или разрешением группы.
- ai.py и handlers/leads.py: черновик первого ответа с нишей, шаблоном и ценами специалиста. Без включённого ИИ — шаблон по правилам. Пользователь сам отправляет ответ; автопереписки нет.
- brain.py: объяснение ошибок владельцу, без управления деньгами.

## Подтверждённые ограничения
1. Общая квота brain.available проверяет число завершённых записей AiCall, не резервирует слот до сетевого запроса. Параллельные запросы могут превысить её. Неуспешные вызовы не записываются, поэтому повторяющиеся сбои не расходуют эту квоту. Для черновиков у администраторов нет личного лимита. Нет общего денежного потолка всех путей ИИ.
2. Для GigaChat/Yandex/Ollama токены оцениваются по длине строки; это не счёт провайдера. Статистика не учитывает полноценную стоимость этих провайдеров. Таблица цен и названия Claude захардкожены; актуальность не проверялась. Не использовать старую документацию как подтверждение нынешней цены/доступности модели.
3. Отдельные поля личности автора не включаются в запрос, однако исходный текст не проходит общую очистку телефонов, @ников и ссылок. Поэтому обещание «контакты никогда не передаются» некорректно.
4. ИИ ограничен уже отобранными сообщениями: пропуски словаря/первичных фильтров более дорогая модель сама не исправит.
5. В publisher.py результат ИИ заменяет результат поиска ограничений по словам. allowed/unknown может убрать найденный запрет из verdict. Требуется правило: явный запрет/платность не ослабляются моделью; отсутствие запрета не становится согласием. Отдельно проверять фразы «коммерция платно», только администратор, противоречивые правила и недоступность ИИ. Автодоступ к рекламе сейчас не включать.
6. JSON для российских провайдеров проверяется приблизительно: типы элементов массивов и ограничения значений требуют усиления. Для Claude успешный JSON в brain.ask не проходит общую локальную валидацию. Нужна единая проверка до действий.
7. Ошибка ИИ в фильтре оставляет решение правилам; ошибка включённого ИИ-черновика показывает сообщение об ошибке, а не автоматически создаёт бесплатный черновик. Различать отсутствие модели и отказ модели.
8. Нет автоматического обучения по успешным сделкам, полного ИИ-секретаря CRM, ежедневных рекомендаций владельцу или автоматических переговоров о рекламе. Разовые запросы условий администраторам не являются такой функцией.

## Приоритет реализации
1. Основа: общая квота с резервированием и учётом ошибок, ограничение параллельности, пауза при повторяющихся сбоях, очищение текстов, статистика по задачам/провайдерам и понятные кнопки выключения. Не менять ключи Modexa и не повышать расходы автоматически.
2. Качество местных заявок: размеченный набор Дагестана по ремонту, перевозкам и красоте, примеры ложных отказов и мусора; измерять пропуски и ошибочные доставки до/после. Обратная связь должна предлагать изменения словарей, а не менять ниши пользователей без их решения.
3. Помощник специалиста: сводка «что нужно, где, срок, бюджет» только по явным данным, вопросы для уточнения, редактируемый ответ по профилю мастера, предложение следующего действия CRM с подтверждением.
4. Помощник владельца: короткая сводка по агрегатам — активные местные специалисты, принятые/отсеянные заявки, доставки, проблемы групп, оплаты и незакрытые заказы; рекомендация и кнопка перехода к первичным данным. Числа считать SQL, моделью только объяснять.
5. Реклама: сопоставление текста с подтверждёнными условиями и ценой площадки, расчёт маржи обычным кодом, несколько вариантов текста без выдуманных гарантий. ИИ не покупает размещения, не выдаёт согласия и не обещает охват.

## Проверка результата
Регрессионные тесты на лимиты/параллельность, ошибки сети, чистку контактов, недоверенные инструкции, запреты рекламы и неверный JSON. Для качества — отдельная размеченная выборка, показатели по нишам и региону. Платные живые сравнения только в согласованном бюджете. Реальные расходы сверять с провайдером; не считать тесты с заглушками доказательством качества модели.

Изменений кода, настроек, ключей, расходов и размещений в этом аудите нет. Дальнейший этап — реализация первого пакета и проверки, затем качество заявок и помощник мастера.
