# Сортировка заявок — 24.11.2026

Запрос владельца: добавить сортировку после понятного времени заявок. Два порядка: сначала свежие (по умолчанию) / сначала старые, по Lead.created_at — времени обнаружения. Это не дата публикации; отдельный пакет published_at остаётся отдельным изменением схемы.

Telegram: 📥 Заявки → кнопка ↕ «Сначала свежие — сменить»; такая же кнопка под карточкой. Выбор сохраняется лично пользователю и применяется в кабинете. На карточке указан текущий порядок. Смена порядка в карточке открывает первую заявку выбранного списка с сохранением ниши/места. Навигационные строки и сортировка сохраняются после «В работу», «Не моё» и других действий.

Кабинет: Заявки → ↕ По времени обнаружения → Сначала свежие / Сначала старые. POST /api/lead-order сохраняет только предпочтение авторизованного пользователя; GET /api/leads возвращает sort. Неизвестные значения/типы дают 400. Необязательный sort на GET закрепляет порядок страниц, не меняя предпочтение. Старые ответы от предыдущих фильтров/порядка игнорируются в интерфейсе.

Порядок SQL: (Lead.created_at, Delivery.id), устойчивый при равных датах и доставке старой заявки позже новой. Граница страниц и положение карточки используют эту пару; якорь доступен только владельцу Delivery и сохраняется при смене статуса. Чужой/исчезнувший якорь API даёт 400 с предложением открыть список заново. Telegram при исчезнувшем якоре открывает доступную карточку, не чужую запись.

Хранение: существующий служебный settings.user_lead_order_<tg_id>, asc/desc; без изменения таблиц/моделей/Compose. Ниши, место, статусы, исходные даты и Modexa не меняются. Откат штатным предыдущим образом, предпочтения можно оставить — старый код их игнорирует.

Проверено локально: 74 профильных теста (новые 5 + multiuser/webapp/bot), затем 5 новых повторно после проверки неверных JSON-типов; compileall, node --check, git diff --check. Отдельно проверены разные даты при обратных id, равные даты, смена статуса курсора, личные настройки, чужой курсор, общая настройка Telegram/API и закрепление страниц при смене предпочтения через другой интерфейс. Полные CI и установка ожидаются. Реальных сообщений/платежей для тестов не делали.
