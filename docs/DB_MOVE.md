# Перенос базы CRM в Россию (PostgreSQL) — пошагово

Зачем: по закону 152-ФЗ данные пользователей из России должны храниться в базе на территории России.
Бот и разведчики **остаются в Алматы** (Telegram в России ограничен), в Россию переезжает только база.

Код к переезду готов и проверен: все автотесты проходят и на SQLite, и на PostgreSQL;
перенос данных — `app/dbcopy.py` (сверяет число строк в каждой таблице).
Время работ — один вечер, бот будет выключен ~15–30 минут.

---

## 0. Что понадобится
- Сервер в России: Selectel, Санкт-Петербург, Shared (10% vCPU, 1 ГБ RAM, 15 ГБ), **Ubuntu 24.04** (не 20.04). ≈926 ₽/мес вместе с IP.
- Адрес (IP) нового сервера — дальше `IP_БАЗЫ`.
- Адрес сервера в Алматы (Irene) — дальше `IP_БОТА` (узнать на Irene: `curl -s ifconfig.me`).
- Пароль для базы — придумайте длинный (20+ символов, только буквы и цифры). **В чат не присылать.**

## 1. Новый сервер: установить PostgreSQL
Зайти по SSH на новый сервер и выполнить:
```
apt update && apt install -y postgresql
sudo -u postgres psql -c "CREATE USER crm WITH PASSWORD 'ВАШ_ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE crm OWNER crm;"
```

## 2. Разрешить подключение ТОЛЬКО с сервера бота
```
echo "listen_addresses = '*'" >> /etc/postgresql/16/main/postgresql.conf
echo "hostssl crm crm IP_БОТА/32 scram-sha-256" >> /etc/postgresql/16/main/pg_hba.conf
systemctl restart postgresql
ufw allow OpenSSH
ufw allow from IP_БОТА to any port 5432 proto tcp
ufw --force enable
```
`hostssl` — соединение только зашифрованное (Ubuntu уже включает SSL в PostgreSQL). Всем остальным порт 5432 закрыт.

## 3. Проверить связь с сервера бота (Irene)
```
cd ~/CRM-bot-tg
docker compose run --rm bot python -c "import asyncio,asyncpg; print(asyncio.run(asyncpg.connect('postgresql://crm:ВАШ_ПАРОЛЬ@IP_БАЗЫ:5432/crm', ssl='require')).get_server_version())"
```
Должно напечатать версию (например `ServerVersion(major=16, ...)`). Ошибка — пришлите её текст (без пароля).

## 4. Перенести данные
```
cd ~/CRM-bot-tg
git pull
docker compose stop bot
docker compose run --rm bot python -m app.dbcopy --to "postgresql+asyncpg://crm:ВАШ_ПАРОЛЬ@IP_БАЗЫ:5432/crm?ssl=require"
```
В конце: «✅ Перенесено строк: N … Сверка числа строк — сошлась». Строки «⚠️ обнулено ссылок / обрезано строк» — это нормально
(старые ссылки на удалённые записи). Если сверка не сошлась — бот НЕ переключаем, старая база цела, пишите мне.

## 5. Переключить бота на новую базу
```
echo 'CRM_DATABASE_URL=postgresql+asyncpg://crm:ВАШ_ПАРОЛЬ@IP_БАЗЫ:5432/crm?ssl=require' >> .env
docker compose up -d --build
```
Проверка: приходит «🟢 Бот запущен», затем ⚙️ → 📋 Состояние бота → 🧪 Самопроверка — «База данных: отвечает».
Через сутки в «Копия базы» появится первая копия уже из новой базы (файл `data/backups/crm-ДАТА.db`, раз в неделю — вам файлом).

## 6. Если что-то пошло не так — откат за минуту
```
sed -i '/^CRM_DATABASE_URL=/d' .env
docker compose up -d
```
Бот вернётся на старую базу SQLite (`data/crm.db` не удаляется при переносе). Но всё, что пришло после переключения, в ней не появится.

## 7. После успешного переезда (через неделю)
- Старый файл `data/crm.db` и старые копии в `data/backups/` — удалить (это данные людей вне России).
- Подать уведомления в Роскомнадзор: об обработке персональных данных и о трансграничной передаче (бот в Казахстане).
- Поправить политику конфиденциальности: где хранятся данные.

## Важно знать
- Бот в Алматы, база в Петербурге: каждый запрос к базе идёт ~60–80 мс. Для 10–100 пользователей это незаметно.
- Если связь между серверами пропадёт, бот покажет ошибки и сам переподключится, когда связь вернётся.
- В `docker-compose.yml` база берётся из `CRM_DATABASE_URL`; пока этой строки в `.env` нет — работает старый SQLite.
