# План: CRM ищет заявки не только в Telegram (15.10.2026)

Статус: **план согласован в разговоре, код не начат.** Решение, с чего начинать, ждёт слова владельца.

## Идея
Все источники сходятся в одну точку — `services/intake` → `distribute` → `notify` → CRM (`services/pipeline.Incoming`).
Новый источник = новый «вход», который приводит сообщение к `Incoming`. Остальное (антиспам, дубли, ниши, город, раздача, CRM, тарифы) работает как есть.

Как «одно целое»:
- у заявки поле **источник** (`tg`, `vk`, `web`, `rss`, `wa`…), в карточке значок источника и ссылка на оригинал;
- один раздел **🛠 Управление → 🌐 Источники**: список источников, вкл/выкл, число заявок за сутки (по правилу интерфейса: всё видно и управляемо кнопками);
- статистика по источникам (заявки и оплаты) — видно, что окупается;
- одна CRM для клиента, откуда бы он ни пришёл.

## Правила (те же, что для Telegram)
- Только открытый контент и официальные API, без чужих аккаунтов и закрытых переписок.
- Текст, имя и публичная ссылка автора хранятся не дольше `lead_keep_days` (90).
- Политику конфиденциальности (`docs/PRIVACY_POLICY.md` и страница на Telegraph) дополнять списком источников.
- Сервер 1 ГБ: только лёгкие источники (опрос по расписанию, без браузеров).

## Источники: что можно / нельзя
| Источник | Решение |
|---|---|
| Вебхук/форма с сайта пользователя (`POST` с личным ключом) | ДА, первым — нужен всем остальным |
| ВКонтакте (открытые сообщества, стена, комментарии), официальный API | ДА, вторым (ключ приложения VK — владелец регистрирует, в `.env`) |
| RSS и ленты (форумы, вакансии через официальные API) | ДА, по желанию |
| Почта (пересылка писем в CRM) | ДА, по желанию |
| Кнопка «🔎 Искать на Авито/Юле/в Google» в карточке/профиле (просто ссылка на поиск) | ДА, вместе с основой |
| Свой аккаунт Авито пользователя через официальный API (его собственные чаты → CRM) | ПОЗЖЕ, условия доступа уточнить |
| Авито, Юла, Profi, YouDo — чтение/парсинг объявлений | НЕТ: запрещено правилами площадок, риск блокировки IP; в объявлениях предложения, а не «ищу мастера» |
| Instagram, Facebook | НЕТ: нет легального доступа |
| WhatsApp (общие группы) | ТОЛЬКО ЭКСПЕРИМЕНТ, см. ниже |

## WhatsApp: условия (решает владелец)
Официального способа читать группы нет; неофициальные библиотеки (Baileys / whatsapp-web.js) нарушают правила WhatsApp и ведут к бану номера. Автор — только номер телефона, а в правилах проекта записано «не собирать номера» — менять осознанно + обновить политику. Мост на Node.js 150–300 МБ — на отдельный недорогой сервер, не на основной. Мост шлёт сообщения в CRM через тот же вебхук, чтобы бан номера не ломал остальное. Нужны: отдельная SIM, согласие на риск блокировки, решение по номерам, отдельная машина.

## Порядок работ
1. **Основа:** `leads.source`, раздел «🌐 Источники», статистика по источникам, кнопки поиска по Авито/Юле/Google, `Incoming.source/link`.
2. **Вебхук для сайтов:** личный ключ у каждого пользователя, адрес приёма, кнопка «Мой ключ» в 👤 Профиль и в кабинете, лимит запросов, антиспам как у остальных.
3. **ВКонтакте** через официальный API.
4. **RSS / почта** — по желанию.
5. **WhatsApp-мост** — только если владелец принял условия выше.
6. **Свой аккаунт Авито** — когда появятся пользователи, которым нужно.
