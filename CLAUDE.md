# CRM-bot-tg — заметки для продолжения работы

Владелец общается по-русски, с телефона (Termius + Telegram). Объяснять просто, по шагам, с готовыми командами.
Ключи, токены, пароли в чат не просить и не показывать.

## Главные правила
- **Журнал для владельца — `docs/DONE.md`** (простым языком: ждёт / отложено / сделано по датам). В конце КАЖДОЙ сессии дописать туда сделанное одной строкой с датой и перенести пункты между разделами.
- **Бот модерации (`abdylzhelil/tg-group-bot`) не трогать**: всё, что в нём сделано, не менять и не удалять,
  он должен работать как раньше. Единственное наше дополнение там — `bot/core/crm_feed.py` (передача сообщений
  в CRM, выключено без `CRM_FEED_URL`/`CRM_FEED_TOKEN`). Всё новое по продажам/клиентам — только в CRM-боте.
- Боты разные, но помогают друг другу: бот модерации — «разведчик» для CRM (передаёт сообщения групп,
  которые владелец включил в CRM: 🛠 Управление → 🔍 Группы → 🛡 Бот модерации).
- Никаких чужих аккаунтов пользователей, никакого сбора ников/номеров людей, только открытые группы.
- Главная ветка в обоих репозиториях: `ccr-a042c0a9-cjx9fv` — на ней стоит сервер. Сессии работают в своей ветке (`ccr-…`), в конце сессии она же пушится в главную: `git push origin <своя>:ccr-a042c0a9-cjx9fv` (только вперёд, без force). Обновление сервера: `git checkout ccr-a042c0a9-cjx9fv && git pull`.

- **Правило интерфейса (владелец, 15.10):** всё, что бот или кабинет создаёт/меняет, должно быть видно и управляемо кнопками. Новый статус или список — сразу кнопка в меню (с числом), возможность вернуть/исправить (не тупик), настройка — в ⚙️. Владелец работает с телефона и не помнит команды. Перед сдачей проверить: «где это найти в меню и как отменить?»

## Сервер
- Selectel, сервер «Irene», Алматы, Ubuntu 24.04, 1 ГБ RAM + 2 ГБ swap. Оплата почасовая — следить за балансом.
- CRM: `/root/CRM-bot-tg` (SQLite в `data/`), бот модерации: `/root/tg-group-bot` (Postgres, Redis, backup, monitor).
- Общая сеть Docker `tgbots`; CRM доступен боту модерации как `http://crm:8090` (секрет FEED_TOKEN / CRM_FEED_TOKEN).
- Обновление CRM: `cd ~/CRM-bot-tg && git pull && docker compose up -d --build`
- Вход по SSH только по ключу (пароль выключен).

## Что сделано в CRM-боте
- Многопользовательский режим: регистрация (ниши → город → заявки за сутки), у каждого свои ниши/город/минус-слова/
  тишина/шаблон/цены/заявки (`deliveries`)/CRM. Тарифы: free (5/день, задержка 30 мин) и full (выдаёт админ).
  Одну заявку получают ≤5 пользователей (платные первыми), админы — все. Спам-голоса: 3 или админ → общий ЧС.
- Источники заявок: разведчик (Telethon, ключи api_id/hash в `.env`, аккаунт добавлен), бот в группах
  (privacy mode off), бот модерации (feed). Общая база: где уже есть наш бот — другой не вступает.
- Разведчик: поиск групп → одно сообщение «найдено N» → отбор списком; пауза/стоп; до 10 вступлений в день;
  группы в папках «🔍 Разведка», звук выключен; ротация.
- Меню: сворачиваемая клавиатура, админские разделы в «🛠 Управление», команды в кнопке «Меню», фолбэк на меню.
- Обновление базы без потери данных: `app/migrate.py` (добавляет новые колонки сам).
- Тесты: `pytest` (310+), общая обвязка в `tests/conftest.py` (`maker`, `tgbot`, `make_user`).

- Этап 2 сделан: 🌐 Каталог (`handlers/catalog.py`, `submissions.py`, `services/catalog.py`): ссылка → проверка через Bot API →
  ниша → город → одобрение админом (🔍 Группы → 📝 От пользователей) → каталог. Бонус +1 день 💎 за каждые N (`bonus_leads`)
  заявок из группы автора. Открытые каналы: `scout/channels.py` (опрос `t.me/s/`, заявка — только если в посте есть @контакт).
  Группы: колонки `kind`, `submitted_by`, `catalog`, `category_id`, `last_post_id`, `bonus_rewarded`; статусы `draft/pending/rejected`.

- Этап 3 сделан: рефералы (`services/referrals.py`, `plans.py`; награда +`ref_days` обоим после настройки приглашённого,
  `ref_percent`% пригласившему от бонусных дней приглашённого за группы) и «📨 Коллеге» (`leads.pass_to`, `Delivery.from_user`).
  Процент от **оплат** приглашённого — только когда появится оплата (этап 5). Колонки: `users.referred_by/ref_rewarded`, `deliveries.from_user`.

- Этап 4 сделан: заявки делятся **поровну по количеству, не по времени** (`distribute.recipients`: k = ⌈людей / заявок ниши за
  сутки⌉ с наименьшей нагрузкой за сутки; много заявок — у всех разные, мало — одинаковые, но по очереди с интервалом `share_gap_min`=2 мин, первым автор группы, затем выше уровень — раньше, при равных — меньше заявок за сутки). Автор группы из каталога всегда получает
  заявки своей группы сразу и мимо лимита. Уровни и рейтинг: `services/levels.py` (`users.level`), «🏆 Рейтинг» в каталоге.
  Время используем только как очередь внутри одной общей заявки; фору «автору на N минут раньше всех» владелец не хочет.

- Этап 5 сделан: оплата через Telegram Payments (`handlers/payments.py`, `services/payments.py`, таблица `payments`;
  `PAYMENT_PROVIDER_TOKEN` в `.env`, цены `price_30/90/365` в настройках, по умолчанию 0 = не продаётся; пригласившему `ref_percent`%
  от купленных дней) и публичный канал (`services/public_stats.py`, `STATS_CHANNEL`; только агрегаты, без имён/ников/текстов).

- Свои ниши: `services/niches.py`, кнопка «➕ Предложить свою нишу» в 🎯 Мои ниши, одобрение `nc:ok/no` в `handlers/categories.py`;
  `categories.pending/proposed_by/proposed_at`; ожидающая ниша невидима и не ловит заявки. Слова ниши можно менять в 🗂 Категории.

- Защита и надёжность: бэкап SQLite `services/backup.py` (data/backups, 7 копий), `/terms` `/paysupport`, напоминание о конце 💎
  (`main.expiry_once`), лимит наград за приглашения `ref_limit`, потолок бонусных дней `bonus_max_days` (оплата без потолка),
  выручка в статистике админа. Тесты: `tests/test_hardening.py`.

- Меню ⚙️ Настройки разбито на разделы (`settings.SECTIONS`, короткие подписи `settings.SHORT`): новая настройка = запись в
  DEFAULTS, LABELS, SHORT и один из SECTIONS (тест проверяет).

- Возврат: кнопка у админа под «💰 Оплата» (`handlers/payments.py` rf:*, `services/payments.refund`): деньги через ЮKassa API
  (`YOOKASSA_SHOP_ID`/`YOOKASSA_SECRET_KEY`, идемпотентно по `refund-<id>`) + снятие дней платежа. `payments.provider_id` — id платежа ЮKassa.
  Бонус пригласившему при возврате не отзывается. ВАЖНО: платежи, сделанные до этого обновления, без provider_id — возврат только вручную.

- Оплата по ссылке (СБП): `payments.create_link/check_links`, `handlers/payments.process_links/link_loop`, таблица `pending_links`;
  платёж создаётся с `capture=true` и БЕЗ `payment_method_data` (иначе СБП не покажется). Окно Telegram sendInvoice СБП не поддерживает (ответ поддержки ЮKassa).

- Рассылка (`handlers/broadcast.py`, 🛠 Управление → 📣 Рассылка) и оповещения: `notify.alert_once` (кулдаун 15 мин), глобальный
  обработчик ошибок в `setup.build`, «🟢 Бот запущен» при старте, тревоги из фоновых задач `main.py`.

- Проверка «я не бот» (`bot/captcha.py`, `users.verified`; в `access.UserMiddleware` непроверенные не-админы видят только её) и чистка
  пустых аккаунтов (`users_admin.empty_users`, кнопка «🧹 Убрать пустые аккаунты»). Колонка verified по умолчанию True — у старых пользователей проверки нет.

- Автоудаление пустых аккаунтов: `services/cleanup.py`, `main.cleanup_loop` (раз в 6 ч), настройки `cleanup_days` (по умолчанию 7, 0 — выкл)
  и `cleanup_warn_days` (1): сначала предупреждение с кнопкой `reg:go`, удаление после его срока; заблокировавших бота удаляем по сроку. `users.warned_at`.

- Срок возврата: настройка `refund_days` (3; 0 — без возврата), текст в `/terms` и `/paysupport` (`payments.refund_line`).

- Автоматика владельцу: еженедельная отправка копии базы файлом (`backup._weekly_send`, ключ `backup_sent_at`), напоминание про чеки
  (`services/receipts.py`, 5-го числа после 10:00, `main.receipts_loop`).

- Реклама для админов групп: `services/ads.py` (`groups.ad_until/ad_spent/ad_pending`), заказ `ad:ask/go` в «Мои группы», подтверждение `adm_ad:ok/no`
  в `submissions.py`; показывается в каталоге (первыми, 📢) и в канале статистики. Цена `ad_leads`=20, срок `ad_days`=7. Лицензия бота модерации — вручную.

- Конец тарифа: `main.expiry_once` (напоминание, «закончился» → plan=free). Автопродление: `payments.renew_due` (`users.renew_method/renew_days/renew_for`,
  `pending_links.auto`, настройка `autorenew`=0 пока ЮKassa не разрешит сохранение способа оплаты; при возврате отключается). Лицензия: `services/licenses.py`
  (`groups.license_until/off/rewarded`, настройка `license_enabled`=0), админ-раздел 🪪 Лицензии, `GET /feed/license`. ВАЖНО: бот модерации этот запрос НЕ делает — менять его только с разрешения владельца.

- `/deleteme` (`services/erase.py`), «сторож» (`services/heartbeat.py`, `HEARTBEAT_URL`), воронка в 📊 Статистике (`stats.funnel_text`), памятка после регистрации (`profile.finish_onboarding`).

- Черновик ответа: по умолчанию БЕСПЛАТНЫЙ по правилам (`services/draft.py`), кнопка `lead:ai:<id>` всегда (`leads.send_ai_draft`). Claude (`services/ai.py`, `anthropic` SDK,
  `AsyncAnthropic`, `fallbacks="default"` для opus/sonnet, таблица `ai_calls`, настройки `ai_*`) ВЫКЛЮЧЕН по умолчанию (`ai_enabled`=0): владелец боится расходов; включается
  ключом `ANTHROPIC_API_KEY` + `ai_enabled=1`. В запрос не передаём данные автора заявки.
